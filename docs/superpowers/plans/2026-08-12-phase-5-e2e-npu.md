# Phase 5 End-to-End Models, PTO Trace Import, and NPU Implementation Plan

**Status:** Approved for execution

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. This plan is executed inline in the Phase 5 worktree. Each task follows red-green-refactor and ends in one reviewable commit.

**Goal:** Deliver the Phase 5 roadmap exit gate: deterministic DavinciOO trace import, real runtime statistics and event output, six complete golden examples, and a hierarchical superscalar NPU that consumes canonical PTO trace and demonstrates concurrent dependency-aware issue with in-order retirement.

**Architecture:** Keep the public runtime boundary exactly `pto-trace@0.1`. A repository-local adapter converts the pinned DavinciOO JSONL shape into canonical trace bytes. The harness loads the validated typed trace once and injects it into generated models before simulation. Runtime observations are committed alongside state and serialized by the harness. Small models and the NPU use typed C++ policies behind generated static topology; JSON remains isolated to the trace/harness boundary.

**Tech Stack:** Python 3.11+ standard library, C++20, LLVM/MLIR 22.1.8, ACIR/ACSim, gfsim, RFC 8785/I-JSON, GoogleTest, LLVM lit/FileCheck, Python `unittest`, CMake/CTest, Chrome Trace Event JSON.

## Global constraints

- The global contract epoch remains exactly `0.1`.
- The public CLI remains the exact existing ten-command surface; the adapter and Perfetto packer are repository development tools, not installed commands.
- Generated simulators accept only canonical `pto-trace@0.1`; raw DavinciOO JSONL is rejected by normal run preflight.
- The imported source shape is pinned to DavinciOO commit `e73633301cabed0d871ea5ff66e76a91df870aeb` and PTO-ISA commit `f6d0567c1cae2d6a7b0ebaf7ad0e3b93f8a39da3`.
- Trace JSON parsing occurs only in the trace subsystem and cold harness path. Architecture components consume typed records or typed transactions.
- Statistics and events observe committed Xfer state only and cannot affect scheduling, arbitration, or termination.
- Stable output never includes absolute paths, wall-clock values, process IDs, pointer values, allocation order, or host scheduling order.
- Every task starts with a failing focused test, records the RED reason in the commit history or test name, runs the focused and affected broad suites, and ends in one reviewable commit.
- Preserve unrelated user work, including the untracked `phase-1-pr-description.md` in the primary checkout.
