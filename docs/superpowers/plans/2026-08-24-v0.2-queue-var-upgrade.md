# Agentic Circuit v0.2 Queue/Var Upgrade Implementation Plan

**Status:** Executing

**Goal:** Complete Issues [#9](https://github.com/PTO-ISA/agentic-circuit/issues/9),
[#10](https://github.com/PTO-ISA/agentic-circuit/issues/10), and
[#11](https://github.com/PTO-ISA/agentic-circuit/issues/11), then prove that a
simple serial Python model generates a typed, queue-wired gfsim C++ model with
the same declared behavior as the checked-in DavinciOO reference and can also
lower through a versioned PYC IR artifact to external `pycc`.

**Authority:** The proposed semantics are defined by
[`agentic-circuit-queue-var-v0.2-proposal.md`](../../specs/agentic-circuit-queue-var-v0.2-proposal.md).
The current active `0.1` contract remains green while this long-running phase
branch builds the replacement. The final integration performs one hard break,
removes the old surface, and changes the complete epoch to `0.2` without aliases.

## Architecture invariants

- Python remains serial-looking and does not declare module ports or queue wiring.
- Statement-level stream variables become `!ac.queue<T>`; lambda/token values
  become immutable `!ac.var<T>`.
- `ac.var<T>` has latency zero. `ac.queue<T>` is stateful and has latency at
  least one tick.
- Payload and nested array/map/set collection shapes are compile-time fixed.
- Queue runtime indexing lowers to official select/route/arbitrate structure;
  it never creates a dynamic queue pointer.
- Every consuming statement is one atomic firing by default; `with ac.atomic()`
  may enlarge that firing.
- Multiple consuming uses insert strict atomic broadcast; buffered fanout is
  explicit.
- Users cannot define opcodes or private C++/PYC/Verilog providers.
- The repository-owned opcode inventory contains common hardware building
  blocks, not application-specific decode/dispatch stages.
- Generated C++ targets the deterministic Agentic gfsim proposal/Xfer runtime.
  The DavinciOO model is a topology/template/behavior oracle, not the scheduler.
- ACIR-to-PYC uses a canonical external artifact and pinned `pycc` process
  boundary. gfsim and RTL compare refinement observations, not internal cycles.

## Delivery sequence

### Queue/Var ACIR foundation

- Add immutable `!ac.var<T>` and stateful `!ac.queue<T>` payload types.
- Add fixed array/map/set collection types with canonical key/member order.
- Define repository-owned opcode declarations, role metadata, and variadic
  Queue/Var signatures.
- Define peek, pop, push, atomic firing, strict broadcast, selection, route,
  merge, feedback, state, memory, observation, and verification semantics.
- Add graph verification for producer/consumer cardinality, stateful cycles,
  effects, ownership, and frozen topology.

### Simple serial Python frontend

- Replace the v0.1 symbolic surface with Queue/Var/Const and immutable Python
  structure values.
- Implement real lexical `with ac.scope()` construction and inferred boundaries.
- Capture pure lambda token regions and infer Queue inputs/results.
- Lower statements to atomic firing rules.
- Implement compile-time collections, static expansion, runtime selection,
  conditionals, bounded feedback loops, and strict broadcast insertion.
- Provide source-oriented diagnostics for every rejected Python construct.

### ACIR optimization and deterministic gfsim

- Canonicalize scopes, collections, Queue/Var types, control flow, broadcasts,
  firing groups, stable IDs, and activation adjacency.
- Optimize only Var combinational regions unless Queue semantic preservation is
  proved.
- Extend typed `SimQueue<T>` with immutable payload traits, exact latency, and
  atomic multi-queue transactions over proposal/arbitrate/Xfer.
- Generate parent-owned typed queue collections and child borrowed references.
- Generate readable template specializations, static dispatch, and manifests.
- Express the DavinciOO reference topology with official building blocks and
  pass its 15-record/453-cycle smoke contract from Python-generated C++.

### PYC and Verilog refinement

- Freeze a versioned canonical PYC artifact and pinned external `pycc` identity.
- Lower Var, Queue, immutable payloads, collections, atomic firing, routing,
  arbitration, state, memory, feedback, hierarchy, roles, and probes.
- Run PYC C++ versus Verilog cycle equivalence.
- Run gfsim versus PYC/Verilog refinement observation comparison.
- Record all tool identities and deterministic artifact hashes in manifests.

### Hard-break integration and audit

- Change the complete contract epoch to `0.2` in one lockstep integration.
- Rename `ac.std.*` to the unified `ac.*` catalog and remove all aliases,
  extension-provider surfaces, and v0.1 compatibility code.
- Replace schemas, manifests, capabilities, diagnostic catalog, documentation,
  fixtures, and installed contracts together.
- Run complete Debug, Release, sanitizer, static-analysis, Python, lit, CTest,
  install, determinism, replay, reference, PYC, Verilog, and refinement gates.
- Audit every requirement in Issues #9–#11 and the proposal manual before merge.

## Checkpoint rule

Each checkpoint starts with a focused failing test, implements one vertical
contract slice, reruns the affected broad gates, and ends in a reviewable commit.
Temporary dual `0.1`/`0.2` test fixtures are allowed only on this phase branch;
the final hard-break checkpoint deletes the `0.1` surface before integration.
